# H5 · Decodificación restringida por gramática para las llamadas a herramienta

estado: abierto
gravedad: media
hito: M2

## SINTOMA
lo que hace: cuando el cerebro emite un `<tool_call>` con JSON roto, el bucle le devuelve
  la queja y le pide que reintente (`plantilla.analizar_llamadas` → `bucle.turno`). Eso
  cuesta **una vuelta entera**: prefill del contexto completo más la generación.
lo que debia hacer: hacer que el JSON roto sea imposible. En cuanto el modelo emite
  `<tool_call>`, se restringe la decodificación a la gramática del esquema de esa
  herramienta: los tokens que romperían el JSON tienen probabilidad cero y no se pueden
  muestrear.

## CAUSA
Sin escribir. Es una técnica conocida (GBNF de llama.cpp, Outlines, `xgrammar`), pero aquí
hay que implementarla sobre el bucle de decode propio de H2, así que depende de él.

**Antes de escribirla hay que medir cuánto duele**: si un 2 % de las llamadas salen rotas,
esto es una optimización prematura; si es un 20 %, es la palanca más rentable del arnés.
La cifra sale de las trazas de las carreras del banco (`Resultado.traza`), y no se sabrá
hasta tener cerebro real. **No implementar antes de tener esa cifra.**
